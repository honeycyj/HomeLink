# HomeLink

面向 Apple Silicon Mac 的 macOS 26 及更新系统的菜单栏远程连接工具，使用 SwiftUI 原生场景、Settings 和 Liquid Glass。

仅在客户端 Mac 安装 HomeLink。远程 Mac 使用系统自带的远程登录和屏幕共享，首次手动授权公钥，之后通过菜单栏连接。支持保存多台设备，同时连接一台。

**当前状态：可自行安装的未公证测试版。** 使用者需要自行允许首次打开，详细操作见下文。公网连接仍需预先配置可达的地址和端口，或使用 VPN。

源码采用 [MIT 许可证](LICENSE)。

## 环境要求

- 使用：Apple Silicon（M 系列）Mac，macOS 26 或更新版本。
- 开发与打包：Xcode 27.1 或更新版本；不依赖第三方 Swift 包。
- 远程 Mac：开启“远程登录”和“屏幕共享”，允许目标用户访问，并授权客户端公钥。

## 运行

用 Xcode 打开 `HomeLink.xcodeproj`，运行目标选择 **My Mac**。也可执行：

```sh
./script/build_and_run.sh --verify
```

此脚本统一负责停止旧实例、构建和启动；支持 `--debug`、`--logs`、`--telemetry`。Codex 的项目 Run 操作配置在 `.codex/environments/environment.toml`。

应用有意只显示在菜单栏，不显示 Dock 图标。没有设备时，首次启动打开添加窗口。通过菜单栏的链条图标打开设备列表。

修改界面后，在 Xcode 按 `⌘.` 停止、`⌘R` 重新运行，再展开菜单查看。如果旧版是独立打开的，先从菜单中退出旧版。共享的 HomeLink Scheme 已包含在工程中，克隆后可直接构建和归档。

## 复制到其他 Mac

当前采用免费、自行允许打开的测试分发方式，不要求购买 Apple Developer Program 会员。

双击工程根目录的 **`打包安装包.command`**，完成后 Finder 会选中最新 DMG，可直接复制给别人。也可执行 `./script/package.sh --reveal`。需要这台打包电脑已经安装 Xcode；使用软件的其他 Mac 无需安装 Xcode。

脚本生成 Release Apple Silicon（arm64）测试包，位于 `Distribution/`，包含 DMG、ZIP、安装说明和 SHA-256 校验文件。开发与打包均只支持 arm64，不包含 Intel 版本。打包不停止正在运行的开发版。将 DMG 中的 `HomeLink.app` 拖入目标 Mac 的“应用程序”即可安装；当前最低系统版本为 macOS 26。

默认保留固定本机开发签名，尚未完成 Developer ID 分发签名和苹果公证。目标 Mac 首次启动可能被系统拦截：确认来源可信后，先尝试打开应用，再到“系统设置 → 隐私与安全性”选择 HomeLink 对应的“仍要打开”，自行确认。受管理的电脑可能不允许此操作，详见 [苹果操作说明](https://support.apple.com/zh-cn/102445)。安装包内也附带这份指引。

安装包只含应用，不包含当前 Mac 的设备、私钥或信任记录；目标 Mac 需单独添加设备并在远程 Mac 授权自己的公钥。“允许打开应用”和“远程 Mac 授权公钥”分别完成一次即可开始使用。

## GitHub 源码与下载包

源码仓库包含工程、代码、测试和打包脚本；DMG、ZIP、校验文件及安装说明作为 GitHub Releases 附件提供，明确标注“未公证测试版”。目前没有自动上传或自动发布流程，打包在开发者本机完成。

## 本机开发签名与钥匙串

本机使用固定的 `HomeLink Local Development` 代码签名证书。签名私钥在登录钥匙串中，`Configuration/Local.xcconfig` 仅记录公开的证书指纹，该文件已忽略提交；没有添加系统根信任。`Debug.xcconfig`、`Release.xcconfig` 和运行脚本共用本机配置与同一个身份，避免临时签名的代码哈希变化导致反复授权。

旧版本的钥匙串授权首次切换到固定签名时，可能需要在系统弹窗输入 Mac 登录密码并选择「始终允许」。SSH 密钥与 Studio 授权无需更换。运行脚本找不到已固定的证书时会停止，不会静默切回临时签名。此签名用于本机开发，不代表已完成分发签名或公证。

`./script/test_keychain_signing.sh` 用一次性项目测试两个不同代码版本能否在不弹出授权界面的条件下访问同一个钥匙串项目，不读取设备私钥。

## 已实现

- 保存多台设备，编辑名称、地址、用户名，移除本机设备记录。
- 首台设备生成 Ed25519 密钥；后续添加默认复用已有公钥，高级选项可改为新密钥。私钥存入本机钥匙串，每台设备有独立存储项目，移除一台设备不会破坏其他设备复用的密钥。
- 设备的「… → 设备设置」始终可进入，连接中也能复制公钥和完整终端授权命令；每台远程 Mac 仍需分别授权一次。
- 在 Studio 手动授权一次的引导与可复制命令，不自动修改远端授权。
- 授权命令按公钥类型和内容去重，保留其他授权；附带 SSH 安全建议注释，不自动修改服务器策略，也不增加安全检查向导。
- 系统 OpenSSH 公钥认证、本机回环地址屏幕共享隧道、主动断开及单连接切换。
- 首次记录主机身份，后续变化时拒绝连接，不自动覆盖信任记录。
- 原生 Settings、可选登录启动与连接中断通知。

密码字段暂时保留但禁用：此版本只走手动公钥授权，不收集或保存远程账户密码。

## 实际连接

在远程 Mac 开启远程登录和屏幕共享，并允许指定用户访问。将本机公钥追加到该用户的 `~/.ssh/authorized_keys`。公网访问仍须预先配置可达地址、端口映射或 VPN。

SSH 隧道只监听 `127.0.0.1`，不直接将屏幕共享对外公开。点击「打开屏幕共享」时调用系统客户端；系统可能另外要求远程账户认证。`已连接` 表示 SSH 认证和本地转发监听已建立，不保证远端屏幕共享已启用。

本机设备资料保存在应用容器的 Application Support/HomeLink 下。移除设备不会撤销 Studio 上已录入的公钥。不同客户端需要分别授权各自公钥。

## 验证范围

连接使用系统 `/usr/bin/ssh`，直接传入保存的域名，由 OpenSSH 解析；不自行替换 Fake-IP，也不读取终端的 SSH 配置或 agent。网络与握手超时 30 秒，整体启动等待上限 45 秒。失败提示区的「查看连接日志」可定位本次日志，包含网络、握手、公钥认证和转发信息。日志只保留最近 128 KiB，权限 600，不记录私钥内容；可能包含地址、用户名及公钥指纹，分享前请检查。

1.0.1 已将最低部署版本降为 macOS 26，Debug 和 Release 均通过面向 26 的编译与安装包检查。当前验证机器运行 macOS 27，macOS 26 上的首次启动、钥匙串、登录启动和远程连接仍需实机回归。

已通过本机编译、启动、添加表单检查和以下可重复检查：

```sh
mkdir -p .build
xcrun swiftc -default-isolation MainActor HomeLink/Models/RemoteDevice.swift Tests/EndpointTests.swift -o .build/endpoint-tests
.build/endpoint-tests
./script/test_services.sh
./script/test_connection_lifecycle.sh
./script/test_keychain_signing.sh
```

密钥检查只创建临时测试密钥，结束后删除测试钥匙串项目和临时文件。

已在当前 Mac Studio 验证真实公钥认证、SSH 隧道和屏幕共享服务响应。完整桌面交互、长期睡眠唤醒与系统通知授权仍需进一步实机验证。当前为开发版本，尚未完成分发签名或公证。

## 实现约定

- `DeviceRepository` 维护界面快照，`DeviceFileStorage` 在专用后台队列串行读写 JSON；`ConnectionController` 负责单连接请求与状态；`DeviceStore` 协调现有界面、设置和通知。
- 连接状态统一为未连接、连接中、已连接、断开中、失败。切换设备先等待前一次清理完成；被取消或过期的回调不会覆盖新连接。
- 正常退出等待隧道收尾。客户端本地进程守护通过私有管道监测 HomeLink 存活，意外退出时终止自己的 SSH 子进程并清理临时密钥；下一次启动还会清理专用临时目录中的遗留文件。不会操作其他终端的 SSH 会话。
- `./script/test_connection_lifecycle.sh` 覆盖取消、切换、提前退出、终止升级、客户端被 SIGKILL、临时文件清理和旧设备文件兼容。所有进程故障测试使用本机假 SSH，不修改远端配置或真实设备密钥。

- 私钥不出现在设备 JSON、日志、剪贴板或远端命令中。
- 仅在 SSH 认证期间从钥匙串取出临时私钥文件，目录权限 700、文件权限 600；认证后清理。
- `Process` 传递独立参数，不将地址或用户名拼入本地 shell 命令。
- SSH 配置、known_hosts 和身份文件由应用管理，不读取用户的全局 SSH 配置或 agent。
- 因转发需要本机监听，启用客户端及服务端沙盒网络权限；监听地址仍限制为回环地址。
- 参考 Figma 的控件结构、蓝色与间距，系统负责 Light/Dark、菜单和窗口材质。设备使用原生 SF Symbol 显示器图标；未连接为半透明灰底，连接完成后为蓝底白图标。

## 后续开发

- 工程边界与扩展方式见 `ARCHITECTURE.md`。保留单个应用 target，按职责拆分文件。
- 钥匙串、设备 JSON、临时密钥均通过后台服务处理；设备变更使用类型明确的 mutation，避免异步保存时丢失其他操作。
- 诊断日志在内存中保留最近 128 KiB，通常每 500 ms 合并写盘；连接失败、退出和断开时等待最终保存。没有增加设备端软件或修改网络设置。
- 公钥、授权命令、复制反馈由共享组件实现，添加设备与设置页保持一致。
- 换开发电脑时将 `Configuration/Local.example.xcconfig` 复制为 `Configuration/Local.xcconfig`，填写该电脑可用的代码签名证书指纹。证书私钥应留在钥匙串中，不能提交到工程。
